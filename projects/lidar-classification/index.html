3D Point Cloud Classification: From Unsupervised Clustering to Supervised Learning

An end-to-end LiDAR pipeline comparing K-Means, BIRCH, Random Forest, and SVM — and quantifying how high-level feature engineering changes the outcome.

#LiDAR#Python#Open3D#Scikit-Learn#Random Forest#SVM

Overview

Airborne LiDAR produces dense, high-resolution 3D point clouds that need to be segmented into semantic classes before they’re useful for anything — building extraction, ground modeling, urban tree inventory, change detection. The classification itself is the hard part. Point clouds carry no color, no labels, and no immediate semantic structure. Every class boundary has to be inferred from geometry and, when available, from the auxiliary channels that ship with the LAS file.

This project walks through four classification strategies on the same dataset and quantifies how each one performs. The finding is straightforward: unsupervised clustering (K-Means, BIRCH) breaks down on point clouds because the classes aren’t separable in raw XYZ space, and the accuracy ceiling only moves once you engineer features that encode local surface structure — normal vectors, inclination angles, PCA components — and rebalance the training set.

The work was completed as part of the Laser Scanners and Photogrammetry Laboratory at K.N. Toosi University of Technology, under Dr. Mohammadzadeh.

Data & Classes

The dataset is an airborne ALS point cloud (nonground_training.las) with four target classes:

Class ID Label Description
1 Building (Gable Roof) Pitched-roof structures
2 Tree / Vegetation Canopy and low shrubs
3 Ground Bare earth, roads, flat terrain
4 Building (Flat Roof) Flat-roofed structures

Training samples for each class were digitized in Global Mapper using the Select by Drawing Polygon tool, exported back out as separate LAS files (one per class), and re-imported into Python for labeling. The sample counts across classes are roughly balanced by design — an imbalanced training set biases the classifier toward the dominant class, and the goal here was to isolate the effect of algorithm choice, not class distribution.

Reading and Visualizing the Point Cloud

The pipeline starts with a standard reading-and-display step. laspy reads the LAS file, the X/Y/Z channels are stacked into a NumPy array, and Open3D renders the result.

import numpy as np
import laspy
import open3d as o3d
import os

os.chdir(r'C:\Users\USER\Desktop')
las = laspy.read('nonground_training.las')

# LAS → NumPy array
pc = np.vstack([las.X, las.Y, las.Z]).transpose()

# Open3D visualization
PCD = o3d.geometry.PointCloud()
PCD.points = o3d.utility.Vector3dVector(pc)
o3d.visualization.draw_geometries([PCD])

Normal vectors are estimated for every point using a KD-tree search with a 0.1 radius and 30 nearest neighbors. The normal vector at each point describes the local surface orientation, which is the single most informative low-level feature for separating roofs, vegetation, and ground.

PCD.estimate_normals(
    search_param=o3d.geometry.KDTreeSearchParamHybrid(radius=0.1, max_nn=30)
)
o3d.visualization.draw_geometries([PCD], point_show_normal=True)

Unsupervised Classification — K-Means and BIRCH

The first two experiments apply unsupervised clustering directly to the raw features. No labels, no training set — just the geometry, and see how well the clusters line up with the four target classes.

Features used: Z (elevation) plus the Green-Blue ratio index, scaled to [0, 1] with MinMaxScaler.

K-Means with n_clusters=4, max_iter=800:

from sklearn.cluster import KMeans

clustering = KMeans(n_clusters=4, max_iter=800, random_state=0).fit(features)
clustered = clustering.labels_

ClusteredPC = np.vstack([las.X, las.Y, clustered]).transpose()
geom = o3d.geometry.PointCloud()
geom.points = o3d.utility.Vector3dVector(ClusteredPC)
o3d.visualization.draw_geometries([geom])

BIRCH with threshold=0.1, n_clusters=4:

from sklearn.cluster import Birch

clustering = Birch(threshold=0.1, n_clusters=4).fit(features)
clustered = clustering.labels_

Visual Results

Neither algorithm produces a usable segmentation. The failure modes are consistent across both:

  • Vegetation and gable roofs are merged. Both are elevated relative to ground, and the raw Z feature cannot distinguish the sloped surface of a roof from the irregular canopy of a tree.
  • Flat roofs and ground are partially confused in BIRCH, where the low-elevation clusters blend at the boundaries.
  • Gable roofs are essentially not segmented at all. Only the top few vertices of pitched roofs end up in the “tall” cluster, which mostly absorbs vegetation.
  • K-Means splits vegetation across three of the four clusters, which means the clusters do not correspond to semantic classes at all.

BIRCH performs worse than K-Means on every class — a known behavior when the cluster shapes are non-spherical, which is exactly the case for canopy points.

The conclusion from this stage is that clustering in raw (X, Y, Z) space cannot separate LiDAR classes. The geometric separation that distinguishes a pitched roof from a tree canopy lives in the local surface structure, not in the elevation of any individual point. That motivates the supervised experiments.

Supervised Classification — Random Forest and SVM

Supervised methods add labels and require a training set. The same low-level features (Z, plus the Green/Blue index) are used again, and 70% of the labeled points go to training, 30% to testing.

Interpretation

Two things stand out.

Vegetation is the weakest class in both models. RF gets precision 1.00 but recall 0.30 — it only catches a third of the actual tree points, and when it does label something a tree, it’s always right. The model is over-cautious on this class because tree points scatter across a wide range of elevations, and the training samples overlap the roof-elevation band. SVM behaves the opposite way: recall 0.38, precision 0.88 — it throws away trees even more aggressively.

Gable roofs and flat roofs are confused with each other in SVM. This is a known limitation of a linear kernel in (Z, Green/Blue) space: both classes sit at similar elevations, and the only thing separating them is the local surface orientation — which neither feature captures.

The single most informative feature, the normal vector estimated earlier, is not yet in the feature set. That’s the whole point of the bonus section.

Feature Engineering — High-Level Features + SMOTE

The bonus section adds two feature families on top of the low-level set and rebalances the training distribution.

Inclination Angle

The angle between the local surface normal and the horizontal plane. For a flat roof it’s near zero; for a pitched roof it’s in the range of the roof pitch; for vegetation it’s scattered across all angles because canopy points have no consistent normal direction.

inclination_angle = np.arctan2(
    pc[:, 2],
    np.sqrt(pc[:, 0]**2 + pc[:, 1]**2)
)

PCA Components

Principal Component Analysis is applied to the point cloud coordinates, and the top three components are added as features. PCA captures the dominant axes of variation in the local neighborhood — essentially a compressed summary of the surface geometry that is invariant to rotation about the vertical axis.

from sklearn.decomposition import PCA

pca = PCA(n_components=3)
pc_pca = pca.fit_transform(pc)

features = np.hstack([
    las.Z.reshape(-1, 1),
    inclination_angle.reshape(-1, 1),
    pc_pca,
])

SMOTE for Class Balance

Synthetic Minority Over-sampling Technique generates synthetic training examples for underrepresented classes by interpolating between real neighbors in feature space. Applied before the train/test split so the rebalanced distribution is what the model actually sees.

from imblearn.over_sampling import SMOTE

smote = SMOTE(random_state=0)
x_resampled, y_resampled = smote.fit_resample(x, y)

Takeaways

Unsupervised clustering is the wrong tool for this problem. Elevation alone cannot separate a pitched roof from a tree canopy, and clustering algorithms that optimize for Euclidean proximity will always merge them. The failure isn’t a tuning problem — it’s that the raw features carry no information about surface orientation.

Supervised methods fix the labels problem but inherit the same feature limitation. RF with (Z, GB) tops out at 0.82. SVM is worse because it can’t model the non-linear decision boundary between gable roofs and flat roofs in a two-dimensional feature space.

Feature engineering is where the accuracy actually lives. Adding an inclination angle and three PCA components gives the classifier direct access to local surface orientation, which is the signal that separates the four classes. SMOTE then ensures the classifier doesn’t drift toward the majority class during training.

The pipeline is not tuned for the specific dataset — the same feature set, the same scaling, and the same RF configuration will run on any airborne LiDAR tile with similar class definitions. The two steps that matter most for reproducibility are the normal-vector estimation and the inclination-angle calculation, both of which depend on a consistent neighborhood search radius.
