Agisoft Metashape — Close-Range and UAV Photogrammetry

Two photogrammetric reconstructions in Agisoft Metashape: a close-range 3D model of a household object using coded markers and scale bars, and an aerial reconstruction of a 0.24 km² site from 240 drone images with ground control points.

#Photogrammetry#Agisoft Metashape#UAV#SfM#3D Reconstruction#Point Cloud

Overview

Two photogrammetric reconstructions built in Agisoft Metashape, both running the same structure-from-motion pipeline at different scales.

The first is close-range: a household object photographed from 281 angles, reconstructed with coded markers and scale bars to centimeter-level ground resolution. The second is aerial: 240 drone images covering 0.24 km², georeferenced with 16 ground control points and processed down to a 3.2 cm/pixel orthomosaic and DEM.

Both projects followed the same eight-stage workflow: marker preparation, image import, alignment, sparse point cloud cleanup, dense reconstruction, meshing, texturing, and export. The differences are all in scale, sensor geometry, and georeferencing strategy.

Why Photogrammetry

Structure-from-motion recovers 3D geometry from overlapping 2D images. The principle is straightforward: if a feature appears in multiple photographs taken from different positions, its 3D location can be triangulated from the camera poses. Modern software handles the pose estimation, feature matching, and bundle adjustment automatically, but the input data still determines the output quality. Good overlap, sharp imagery, controlled lighting, and stable camera calibration matter more than any processing parameter.

Close-range photogrammetry (any capture distance under 300 m) has become the standard alternative to laser scanning for medium-accuracy 3D documentation. It is cheaper, faster, portable, and produces color information without additional scanning passes. The tradeoff is that it depends on good texture and consistent lighting, and it cannot handle highly reflective or transparent surfaces.

Project 1 — Close-Range Reconstruction

Object: a textile armchair, photographed handheld in a bright indoor environment. Input: 281 images. Camera: Canon PowerShot SX60 HS, 3.8 mm focal length, 1.34 μm pixel pitch, auto mode, no precalibration. Markers: 5 coded targets printed on A4 and placed around the object. Scale bars: 5, measured manually with a tape measure before capture.

Stage 1 — Marker preparation

Coded markers are printed from the Metashape Print Markers dialog. The parameters control marker type (12-bit circular), center point radius, targets per page, and font size. The 12-bit pattern gives each marker a unique signature that the software can identify automatically during the marker detection pass.

![Coded markers prepared for printing](../../assets/Images/Projects/Agisoft%20Metashape%20Projects/Final Product%20(AgiSoft%20MetaShape))

Five of the printed markers were cut out and placed around the object at floor level, in positions that would appear in as many images as possible.

Stage 2 — Image import

Workflow → Add Photos

281 images imported into a single chunk. The camera auto-detected the folder and read EXIF metadata for focal length and pixel size.

Stage 3 — Alignment

Workflow → Align Photos
Accuracy: Highest
Generic preselection: On
Reference preselection: Off
Key point limit: 40,000
Tie point limit: 4,000

Alignment ran on the full set with high accuracy. Result: 15,948 tie points across 255 aligned images, 2.63 px mean reprojection error. The 26 images that failed to align were captured at angles with insufficient overlap and were dropped rather than forced.

The blue rectangles are camera positions, the sparse point cloud is the small cluster of gray points. Every camera that aligned is marked with a green flag in the Photos panel.

Stage 4 — Sparse cloud cleanup

Not all tie points are useful. Some are noise, some are reflections, some are floating artifacts where the matcher found spurious correspondences. These need to be removed before dense reconstruction.

Free Selection and Lasso tools were used to select the outlier regions, then Delete removed them.

Remaining points after cleanup: 15,948 of the original 72,231. That is aggressive. The removed points were all behind the object or on the floor plane, and none of them contributed to the object’s surface.

Stage 5 — Dense cloud

Workflow → Build Point Cloud
Source data: Depth maps
Quality: Ultra High
Reuse depth maps: On

Result: 1.25 million points at 0.352 mm/pixel ground resolution. That resolution is high enough to resolve the textile weave on the armrest.

Stage 6 — Mesh

Workflow → Build Mesh
Source data: Depth maps
Surface type: Arbitrary (3D)
Quality: Ultra High
Face count: High

Result: 4.48 million faces, 2.24 million vertices. Arbitrary surface type because the object is not a terrain-like surface and does not have a preferred orientation.

Stage 7 — Model display modes

Metashape offers four ways to view a model. All four are useful at different stages.

Shaded applies soft lighting and material rendering, giving a realistic preview of the final appearance.

Solid renders the model as an opaque volumetric surface without texturing.

Wireframe shows only the triangle edges, useful for inspecting mesh topology and identifying regions of poor triangle quality.

Confidence is the most useful diagnostic. Every vertex is colored by how consistently it was triangulated. Blue is high confidence, red is low. In this model, the textured seat surfaces are saturated blue, and only the edges and the shadowed underside show any red.

Stage 8 — Texture

Workflow → Build Texture
Texture type: Diffuse map
Source data: Images
Mapping mode: Generic
Blending mode: Mosaic
Texture size: 8192 × 8192

The texture pass uses the source photographs to color every face. Mosaic blending selects the least oblique image for each triangle and feathers the boundary between adjacent triangles.

Stage 9 — Markers and scale bars

Coded markers auto-detected from the photographs (green flags indicate successful detection). Five scale bars were measured with a tape before capture and entered manually into the Reference panel. Metashape uses the scale bars to solve for the model’s real-world dimensions.

Total scale bar error after adjustment: 1.9 mm across a 1 m reference, which sets the absolute accuracy of the model. Relative accuracy within the reconstruction is much higher, since the internal geometry is constrained by the 15,948 tie points.

Project 2 — UAV Reconstruction

Site: an agricultural plot in Iran, roughly 0.24 km². Input: 240 drone images, DJI FC300X camera, 4000 × 2250 resolution, 1.7 μm pixel pitch, 3.61 mm focal length. Flight altitude: 81.8 m above ground. GCPs: 16 ground control points surveyed on the ground. Coordinate system: WGS 84 / UTM Zone 38N (EPSG:32638).

Alignment

Accuracy: Highest
Generic preselection: On
Reference preselection: Source
Key point limit: 40,000
Tie point limit: 4,000

All 240 images aligned on the first pass. Result: 156,907 tie points, 839,291 projections, 0.667 px mean reprojection error. Alignment itself took under three minutes.

![Camera positions and image overlap map](../../assets/Images/Projects/Agisoft%20Metashape%20Projects/Final Product%20(AgiSoft%20MetaShape))

The flight path is a five-lane lawnmower pattern with a cross-strip at each end. Overlap is 80 percent along-track and 60 percent across-track, which is standard for aerial mapping where elevation accuracy matters.

Ground control points

The 16 GCPs were surveyed with GNSS during the ground campaign and imported into the Reference panel. Each one was manually located in the images by filtering to the photos that contained the marker and clicking its exact position.

After adjustment, the GCP residuals are as follows:

These are exceptional for a UAV survey without RTK. The GCP count and distribution across the site are what got the error this low. Fewer points or a clustered distribution would have left the model poorly constrained at the edges.

Outputs

Digital Elevation Model. 25.7 × 17.4 m grid, 3.2 cm/pixel horizontal resolution, 977 points/m² density. Elevation range spans 1.97 to 2.12 km, which reflects the actual topographic variation across the plot.

Orthomosaic. 2.55 GB GeoTIFF, UTM Zone 38N, three-band RGB. The mosaic is a true-scale planimetric view: every pixel has known ground coordinates and no relief displacement. It can be loaded directly into QGIS or ArcGIS for area measurements, feature digitization, or as a base layer for field survey planning.

Tiled model. A hierarchical LOD structure optimized for real-time viewing. Useful when the full-resolution model is too heavy for a specific application.

Pipeline Notes

Alignment accuracy vs processing time. Highest accuracy triples the matching time compared to Medium, but it produces two to three times more tie points. For a project with adequate disk space and a decent GPU, there is no reason to go lower. For a quick preview, Medium is fine.

Reference preselection. When GPS data is embedded in the images, enabling reference preselection cuts alignment time significantly by only matching cameras that are geographically close. On the close-range project this was off, because the images had no GPS and the camera moves in arbitrary directions.

Marker detection tolerance. Default 50 in the Detected Markers dialog works for well-lit, in-focus marker images. Blurry or obliquely photographed markers need a higher tolerance, at the cost of more false positives. Both projects kept the default and got clean detection.

Texture size. 8192 × 8192 is the practical maximum for a single-texture model in most viewers. For very large sites, use multiple texture tiles. Going above 8192 tends to produce files that either fail to load in game engines or exceed VRAM on the target hardware.

Coordinate system choice. Close-range models can stay in local coordinates when there is no need to tie them to a global frame. UAV surveys should always be georeferenced, both so the outputs are usable in GIS and so the GCP adjustment can be evaluated against survey-grade truth.

What the Two Projects Have in Common

The pipeline is identical from alignment onward. What differs is how the two inputs constrain the reconstruction.

The close-range project uses coded markers and measured scale bars to establish absolute scale. Without the scale bars, the model would be geometrically correct but dimensionless. Without the markers, alignment would still work, but adding scale would require a different technique.

The UAV project uses surveyed GCPs to establish absolute position. Without them, the model would float relative to the true world coordinates and carry a systematic tilt error introduced by the flight dynamics and the GPS noise on the camera positions. The GCPs anchor the model and correct that drift.

Both approaches exploit the same principle: give the solver a small number of known-position constraints and let it propagate them across the rest of the network through bundle adjustment.
