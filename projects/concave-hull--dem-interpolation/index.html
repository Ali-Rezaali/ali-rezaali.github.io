Digital Elevation Model Interpolation — IDW, Kriging, and TIN Under Morphological Constraints

A systematic comparison of three interpolation families on 13,976 elevation points, with and without hard/soft breakline integration, benchmarked by RMSE.

#DEM#Interpolation#Kriging#IDW#TIN#ArcGIS Pro#Geostatistics

Overview

Producing a digital elevation model is one of the few geospatial tasks where the answer is genuinely not obvious until you test it. Three interpolation families — inverse distance weighting, ordinary kriging, and triangulated irregular networks — each claim to be the right tool. Each has a decade of literature behind it. They do not agree.

This project runs all three on the same dataset, with identical training and test splits, and measures the difference. Then it runs each again, but this time feeding the interpolator information about the physical structure of the terrain — rivers, roads, buildings, cliffs — in the form of breaklines. The question is whether the additional structural knowledge actually improves the result, or whether some interpolation methods already handle morphology well enough on their own.

Data Preparation

The elevation dataset (Sample 17) contains 13,976 points in CAD format, with no coordinate system attached. They were imported into ArcGIS Pro, assigned X/Y from the first two fields and Z from the third via Display XY Data, and projected to a working CRS.

Two classes of problem showed up immediately:

  • Spatial outliers — points located far outside the main cluster, which would have forced interpolators to extrapolate over empty space. Removed with a Lasso selection on the point cloud, followed by Inverse Selection and delete.
  • Vertical outliers — points at elevations implausible relative to neighbors. Removed by filtering against the local elevation distribution.

After cleanup, the working set was split 70/30 into training and test data using Subset Features:

Training: 13,976 × 0.7 = 9,783 points
Test:     13,976 × 0.3 = 4,192 points

The split was random. This matters for the interpretation of the TIN results later, and it’s worth flagging as a methodological caveat.

Defining the Working Boundary

Interpolation inside a concave-shaped point cloud requires a concave boundary. A convex hull would have added large triangles of empty space along the coastline and the bay, and every point inside those empty triangles would have been interpolated from a small number of distant controls.

I computed the concave hull in Python using alphashape:

import geopandas as gpd
import alphashape

gdf = gpd.read_file('Elevation Data (Sample 17).shp')

points = []
for geom in gdf.geometry:
    if geom.geom_type == 'Point':
        points.append((geom.x, geom.y))
    elif geom.geom_type == 'MultiPoint':
        for point in geom.geoms:
            points.append((point.x, point.y))
    # ... Polygon and MultiPolygon handled similarly

alpha_shape = alphashape.alphashape(points, alpha=0.01)

hull_gdf = gpd.GeoDataFrame({'geometry': [alpha_shape]}, crs=gdf.crs)
hull_gdf.to_file('concave_hull_output.shp')

The alpha parameter controls how tightly the boundary hugs the point cloud. alpha=0.01 was chosen after testing several values — lower values produce a hull that follows every indent in the point distribution; higher values converge toward the convex hull. 0.01 preserved the bay shape without fragmenting the boundary into multiple components.

The resulting concave hull was buffered and smoothed in ArcGIS Pro so that it could be used as a clipping mask for all subsequent raster outputs. Every interpolator then produced a raster, clipped to this boundary.

Morphological Features

Two classes of breaklines were extracted from the accompanying CAD layers:

Hard Breaklines — abrupt changes in slope or elevation. Includes:

  • Layer 8 (roads, tunnels, bridges, overpasses, roundabouts)
  • Layer 10 (walls, wire fences, hedges)
  • Layer 14 (highways)
  • Layer 15 (streets, alleys)
  • Layer 47 (sand dunes)

Soft Breaklines — gradual transitions. Includes:

  • Layer 1 (orchards, single palm trees)
  • Layer 2 (agricultural land)
  • Layer 18 (water bodies)
  • Layer 19 (canals, streams)
  • Layer 21 (marshes, swamps)

Each vector layer was converted to points with Feature Vertices to Points and merged with the training dataset as additional control points. The merged set was then used to run each interpolator a second time.

One detail that matters: when merging, the Z value must be taken from the Shape.Z field, not the third numerical field. Line features converted to points do not carry a third field, so any script that reads “the third field” silently produces nothing useful. This cost a full re-run to catch.

IDW — Inverse Distance Weighting

IDW assigns each unknown location a weighted average of nearby control points, with weight proportional to the inverse of distance raised to a power p. Higher p emphasizes nearer points; lower p treats all points in the search radius more equally.

Eight power values were tested, from 0 to 30:

Power RMSE (no morphology) RMSE (with morphology)
0 — —
0.5 4.346 3.980
1.0 4.346 3.980
3.0 3.182 3.157
5.0 3.277 3.257
8.0 3.512 3.457
14.0 3.778 3.696
30.0 4.012 3.912

Power 0 is undefined in ArcGIS Pro — it returns a flat average rather than a distance-weighted surface, which is why the row is empty.

Two patterns emerge:

  1. Power 3 is optimal for this dataset. Error drops from 4.35 at p = 1 to 3.18 at p = 3, then rises again as p increases toward 30. Very high power effectively reduces the interpolation to nearest-neighbor, which introduces discontinuities.
  2. Morphological features help consistently, but modestly. The improvement is largest at low p (from 4.35 to 3.98) and smallest at p = 3 (from 3.18 to 3.16). At higher powers the model already trusts individual nearby points more, so the additional breakline information has less room to influence the surface.

Visually, the difference between the two runs is striking. Without morphology, roads and river channels are smoothed over. With morphology, they emerge as ridges and depressions in the elevation surface — physically correct, and impossible to recover from elevation points alone.

Kriging — Ordinary Kriging

Kriging is a geostatistical interpolator that models spatial autocorrelation explicitly through a semivariogram. Unlike IDW, it does not assume that influence decays as a fixed power of distance — it estimates the decay from the data.

Five semivariogram models were tested:

Model RMSE (no morphology) RMSE (with morphology)
Spherical 4.77 2.43
Circular 4.07 4.29
Linear 4.72 2.63
Exponential 2.22 2.44
Gaussian 4.68 3.92

Two findings worth unpacking.

Without morphology, Exponential is the clear winner at RMSE 2.22. This is the best single result across all three interpolation families. The Exponential semivariogram model assumes spatial correlation decays quickly with distance and then flattens out — a good fit for the undulating terrain of the study area.

With morphology, the picture inverts. Exponential accuracy degrades slightly (2.22 → 2.44), while Spherical improves dramatically (4.77 → 2.43). The breaklines add sharp-edged constraints, which the Exponential model interprets as noise because its correlation structure is smooth. The Spherical model has a finite range and a more abrupt transition at the sill, which suits the constrained surface better.

The safest general recommendation for a first pass on this kind of terrain would be Exponential without morphology — it produces the lowest RMSE, and its errors are smooth and predictable. Adding morphology is justified only if the sharp features (roads, rivers) need to be visible in the final product, in which case Spherical is a better choice even if its raw RMSE is slightly higher.

TIN — Triangulated Irregular Network

A TIN is a vector interpolator: it connects control points into a mesh of triangles and stores elevation per vertex. Unlike IDW and Kriging, it has no cell size to tune and no semivariogram to fit. Its behavior is determined entirely by how the input points are connected.

Configuration RMSE
TIN without morphology 2.82
TIN with morphology 3.03

The plain TIN beats every raster method except Kriging Exponential. Adding morphology degrades accuracy — the reverse of what happens with IDW.

Two explanations are plausible, and both are worth stating:

  1. Hard breaklines force abrupt facet boundaries that TIN already handles naturally. A TIN built from elevation points alone will already form sharp edges at ridges and valleys because the triangle geometry is data-driven. Explicit breakline constraints can over-sharpen these edges and introduce spurious steps.
  2. Random test split bias. The 30% test points are drawn at random, not strategically. Some fall on flat terrain where all methods perform equally; a few fall near sharp features where a breakline-constrained TIN might deviate more. With only 4,192 test points, this sampling effect is not fully averaged out.

The report’s honest recommendation is that a manually selected test set — points placed specifically on ridges, valleys, and flat areas — would give a cleaner comparison. That is future work, not something this exercise could settle.

Comparison and Final Recommendation

Aggregating the best configuration from each family:

Method Best Config RMSE
IDW p = 3, with morphology 3.157
TIN no morphology 2.82
Kriging Exponential, no morphology 2.22

Kriging with an Exponential semivariogram and no morphological constraints produces the lowest RMSE on this dataset, and its visual output is the closest to a physically plausible surface. The final recommendation for this site is Kriging Exponential. TIN is a reasonable second choice if a vector representation is required. IDW is the fastest to run and produces acceptable results, but its accuracy ceiling is measurably higher than the other two.

Takeaways

Interpolation method choice dominates morphological input. The RMSE spread between the best and worst methods (2.22 vs. 4.77) is more than double the spread between with-morphology and without (e.g., IDW improvement: 0.19). Picking the right semivariogram model matters more than adding constraint data.

Morphology is not a free improvement. It helped IDW consistently, helped Kriging selectively, and hurt TIN. The physical intuition that “more accurate input → more accurate output” is not reliable here — the interpolator’s internal assumptions interact with the added constraints in ways that are method-specific.

Error metrics are necessary but not sufficient. The RMSE numbers do not capture that the with-morphology IDW surface looks correct — roads and rivers visible as ridges and depressions — while the no-morphology variant smooths them into oblivion. Visual inspection of the final surface, cross-checked against the actual terrain, remains part of the evaluation.
