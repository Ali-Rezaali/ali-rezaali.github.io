Remote Sensing Laboratory — From Pixel to Semantic Map

Eight end-to-end exercises spanning Python image processing, Landsat 8 metadata analysis, radiometric correction, supervised classification, water extraction, and Split-Window sea surface temperature retrieval.

#Remote Sensing#ENVI#Python#Landsat 8#Classification#SST

Overview

A full-semester laboratory course at K. N. Toosi University of Technology’s Faculty of Geodesy and Geomatics Engineering, covering the applied side of remote sensing — the parts that don’t fit into lecture slides. How raw DN values become calibrated radiance. How a header file is actually organized. How atmospheric correction algorithms differ in practice. How the choice of classifier changes the map you produce.

Eight exercises, each building on the last. The thread tying them together is transformation: data moves from instrument to calibration to correction to classification to a usable geographic product, and every step has a decision that materially changes the result.

01 — Histogram Equalization from Scratch

The first exercise was to implement histogram equalization without cv2.equalizeHist — write it from the histogram, the CDF, and the interpolation.

import cv2
import numpy as np

img = cv2.imread('input.jpg', 0)

# Histogram + CDF
hist, bins = np.histogram(img.flatten(), 256, [0, 256])
cdf = hist.cumsum()
cdf_normalized = 255 * cdf / cdf[-1]

# Map original pixels via interpolated CDF
equalized = np.interp(img.flatten(), bins[:-1], cdf_normalized).reshape(img.shape)

The point isn’t the transformation itself — it’s that every line of it is visible. The CDF is the mapping function; the interpolation just smooths the transition between histogram bins. Once you see that, equalizeHist stops being a black box.

The input was a low-contrast photo. After equalization, the histogram flattens out and the visual contrast range expands to fill the full 8-bit space.

02 — Smoothing Filters with Custom Kernels

The second exercise built three smoothing filters from raw kernel definitions — no cv2.GaussianBlur, no cv2.blur. Just a convolution loop.

Three kernels:

  • Gaussian 5×5 — weighted by distance from center, ideal for removing Gaussian noise
  • Weighted Mean 5×5 — same numbers, but interpreted as a linear weighting rather than a Gaussian falloff
  • Mean 7×7 — flat 1/49 weights, the simplest possible smoother

The apply_filter function pads the image with a border of kernel_size // 2 zeros, then walks every pixel and replaces it with the sum of the kernel-times-neighborhood.

def apply_filter(image, kernel):
    pad = kernel.shape[0] // 2
    h, w = image.shape
    padded = np.zeros((h + 2*pad, w + 2*pad), dtype=image.dtype)
    padded[pad:h+pad, pad:w+pad] = image
    
    out = np.zeros_like(image, dtype=np.float32)
    for i in range(pad, h + pad):
        for j in range(pad, w + pad):
            out[i-pad, j-pad] = np.sum(
                kernel * padded[i-pad:i+pad+1, j-pad:j+pad+1]
            )
    return out

The Gaussian kernel produced the smoothest output but also the softest edges. The mean filter is faster but blurs across edges. The weighted mean was the compromise — most of the noise suppressed, most of the edges preserved.

03 — Landsat 8 Metadata Anatomy

The header (MTL) file is where all the calibration constants live. This exercise went through every group in the file:

  • METADATA_FILE_INFO — origin, DOI, data type per band
  • PRODUCT_METADATA — scene ID decoded (path, row, date, processing level)
  • IMAGE_ATTRIBUTES — cloud cover, sun angles, saturation flags
  • PROJECTION_PARAMETERS — UTM zone, datum, grid cell sizes per band group
  • LEVEL1_RADIOMETRIC_RESCALING — the important one. This is where the gain and offset constants live that turn raw DN into radiance and reflectance.

The product ID format is worth memorizing:

LXSS_LLLL_PPPRRR_YYYYMMDD_yyyymmdd_CC_TX

So LC08_L1TP_165035_20220916_20220922_02_T1 means Landsat 8, Level-1 Terrain Precision, WRS path 165 row 35, imaged 2022-09-16, processed 2022-09-22, Collection 2 Tier 1.

Every downstream correction — FLAASH, Flat Field, Log Residuals — pulls its constants from this file. Get the header wrong, every step after is wrong.

04 — Cirrus and Quality Assessment Bands

Band 9 is the odd one out on Landsat 8. Its spectral range (1.363–1.384 μm) is inside a strong water vapor absorption band, which means almost all solar radiation in that range is absorbed before it reaches the ground. On a clear day, the ground is nearly black in Band 9. But high-altitude cirrus clouds reflect before most of the atmosphere is traversed, so they show up bright.

That’s the design: Band 9 is a cirrus detector.

The Quality Assessment (QA) band is the pixel-level metadata companion. Each 16-bit QA value is packed with flags — cloud confidence, cirrus confidence, snow/ice, water, terrain occlusion — laid out across specific bit positions. The lower two bits are boolean (fill, dilated cloud, cirrus, cloud), the upper bits are two-bit confidence levels (0 = none, 1 = low, 2 = medium, 3 = high).

Reading them requires bitwise operations, not visual inspection. It’s a decoder ring rather than a picture.

05 — Drop-Line Correction and RMSE Benchmarking

Drop lines are what happens when a detector on a pushbroom sensor fails mid-scene. The output is a stripe of zero-valued pixels running the full column length. There’s no recoverable signal in those pixels — the only option is interpolation from neighbors.

This exercise did the full loop:

  1. Injected drop lines artificially into a clean Landsat 8 scene (20 lines, chosen randomly across the image) using rasterio
  2. Corrected them with ENVI Classic’s Replace Bad Lines tool at three different half-width settings
  3. Benchmarked the correction quality with RMSE
import rasterio
import numpy as np
from sklearn.metrics import mean_squared_error

with rasterio.open('reference.tif') as ref:
    ref_line = ref.read(2)[3, :]

    for i in range(1, 4):
        with rasterio.open(f'BadLinesHalfWidth{i}.tif') as src:
            line = src.read(2)[3, :]
            rmse = np.sqrt(mean_squared_error(ref_line, line))
            print(f'RMSEHalfWidth{i}: {rmse}')

Results:

Half-Width RMSE
1 3.29
2 4.27
3 4.80

The tighter the interpolation window, the better the recovery. Wider windows include more neighboring lines, which pulls in pixels from different surface types and blurs the recovered signal. Half-width 1 wins.

06 — Supervised Classification Across Four Corrections

The largest single exercise. Same scene, same training data, same two classifiers — but four different atmospheric corrections applied first, and a full accuracy comparison across all combinations.

The four corrections:

  • Dark Object Subtraction — subtract the scene’s minimum pixel value (assumed to be atmospheric scattering)
  • FLAASH — full radiative transfer model, the industry standard
  • Flat Field — normalize to a known flat-reflectance region
  • Log Residuals — remove illumination, topographic, and gain effects via a log transform

The two classifiers:

  • Minimum Distance — non-parametric, assign each pixel to the nearest class mean
  • Maximum Likelihood — parametric, assumes Gaussian distribution per class and picks the most probable

Then a confusion matrix for each combination, computing Overall Accuracy and Kappa coefficient.

The winner:

Correction Classifier OA Kappa
Dark Subtract Minimum Distance 90.36% 0.880
Dark Subtract Maximum Likelihood 88.54% 0.857
Flat Field Minimum Distance 92.18% 0.902
Flat Field Maximum Likelihood 88.54% 0.857
Log Residuals Minimum Distance 91.14% 0.889
Log Residuals Maximum Likelihood 88.51% 0.856
FLAASH Minimum Distance 92.22% 0.903
FLAASH Maximum Likelihood 88.62% 0.858

Two findings:

  1. FLAASH + Minimum Distance wins overall. The full atmospheric model plus the non-parametric classifier beats every other combination.
  2. Minimum Distance beats Maximum Likelihood on every correction. Counter-intuitive — ML is theoretically more powerful — but Maximum Likelihood is sensitive to the Gaussian assumption, and the training samples here don’t satisfy it cleanly. Minimum Distance doesn’t care about distribution shape.

This is the exercise that best captures the point of the whole lab: the combination of correction and classifier matters more than the choice of either alone.

07 — Water Extraction with NDWI/NDVI Decision Trees

Water extraction from multispectral imagery, using spectral indices and decision trees.

Two indices:

  • NDWI = (Green − SWIR2) / (Green + SWIR2) — for water discrimination
  • NDVI = (NIR − Red) / (NIR + Red) — for vegetation and soil discrimination

Then a decision tree built on the indices:

if NDVI < 0 → Water
else if NDVI < 0.2 → Soil
else → Vegetation

The tree was applied to two images — one calibrated to reflectance, one corrected with FLAASH — and cross-validated against ground-truth ROIs.

NDWI achieved perfect water classification in both images. NDVI was stronger on the FLAASH image, which makes sense — atmospheric correction brings the spectral values closer to physical reflectance, which is what NDVI was designed for.

The final area computation was done two ways: pixel count times pixel area, and polygon-based area in ArcMap. Both returned 1,197,900 m² — a good sanity check that the raster and vector representations agree.

08 — Sea Surface Temperature via Split-Window

The last exercise retrieved Sea Surface Temperature (SST) from Landsat 8’s two thermal bands (10 and 11).

The Split-Window algorithm exploits the fact that water vapor affects the two thermal bands differently. By using the difference between them, you can correct for atmospheric absorption without needing a full atmospheric profile.

The pipeline:

  1. Convert DN to radiance using gain/offset from the MTL file
  2. Convert radiance to brightness temperature using the K1/K2 thermal constants
  3. Regress the two bands against ground-truth SST measurements
# Brightness temperature from thermal band
# T = K2 / ln(K1/L + 1) - 273.15  # in Celsius

Ground-truth control points (30 GCPs) were collected and their pixel values extracted from both bands. A quadratic regression between the two bands produced the final coefficients:

SST = A0 + A1·T10 + A2·(T10 − T11) + A3·(T10 − T11)²

with:

  • A0 = 13.85
  • A1 = −0.00285
  • A2 = −2.80
  • A3 = 0.71

Final RMSE: 0.359 °C. For a course project with 30 GCPs, that’s a tight fit — the Split-Window formulation captured nearly all the variance.

The final map was classified by temperature range using ENVI’s Density Slice tool, producing a graduated color product suitable for the report.

Takeaways

Three things the whole lab reinforced.

Correction matters more than classifier. The single biggest accuracy gain in Project 06 came from switching from Dark Object Subtraction to FLAASH — not from switching between MD and ML. The quality of the input data dominates the quality of the algorithm on top of it.

Non-parametric methods are safer than they look. Maximum Likelihood assumes Gaussian classes. When that assumption breaks — as it does for heterogeneous land cover — Minimum Distance wins despite being conceptually simpler. Model assumptions are load-bearing.

Metadata is not decoration. Every calibration in this lab traced back to a value in the MTL file. Read the header, understand the format, extract the constants. Everything downstream depends on it.
