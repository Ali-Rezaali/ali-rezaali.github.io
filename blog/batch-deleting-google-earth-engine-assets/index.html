Batch Deleting Google Earth Engine Assets

The GEE Code Editor can only delete one asset at a time. This script reconstructs a target set from a naming pattern and removes every match in a single pass.

Published on September 2, 2026

The Code Editor can only delete one asset at a time. That’s fine for a handful of stray images, but once an experiment has generated hundreds of models, composites, or exports that all need to go, clicking through the tree stops being a workflow and starts being a punishment (0/10, not recommended).

The alternative is to describe what should be deleted as a set of paths, generate the full list from a naming pattern, and remove everything in one script.

Why Generate Paths Instead of Listing Them

Two patterns show up in practice. If your assets were named from a template — something like Site-Season-Model-Suffix — you can reconstruct every path from a small set of components, which is what the script below does. If the assets were named by hand with no consistent structure, you’ll need to list them explicitly, but the deletion logic stays the same.

The Script

Run this in a Python environment with the earthengine-api package installed and authenticated. Here, I will use my own set of years, seasons, and variables that I’ve experienced with during the ERA5-Land Downscaling project.

import warnings

# [1] SUPPRESS DEPRECATION & EOL WARNINGS (Python 3.9 EOL / google-auth warnings)
warnings.filterwarnings("ignore", category=FutureWarning)

import ee

ee.Initialize()

# [2] PATH & CONFIGURATION
BasePath = "projects/your-project/assets/Path/To/Models/"
ModelSuffixes = ["T2M", "WS", "SM"]

# [3] DEFINE TARGET LABELS BY YEAR (4 SEASONS PER LINE)
# Uncomment the whole yearly row (or specific items) to purge
SiteOneLabels = [
    "S1-2020", "S2-2020", "S3-2020", "S4-2020",
    "S1-2021", "S2-2021", "S3-2021", "S4-2021",
    "S1-2022", "S2-2022", "S3-2022", "S4-2022",
    "S1-2023", "S2-2023", "S3-2023", "S4-2023",
    "S1-2024", "S2-2024", "S3-2024", "S4-2024",
    "S1-2025", "S2-2025", "S3-2025", "S4-2025",
]

SiteTwoLabels = [
    "S1-2020", "S2-2020", "S3-2020", "S4-2020",
    "S1-2021", "S2-2021", "S3-2021", "S4-2021",
    "S1-2022", "S2-2022", "S3-2022", "S4-2022",
    "S1-2023", "S2-2023", "S3-2023", "S4-2023",
    "S1-2024", "S2-2024", "S3-2024", "S4-2024",
    "S1-2025", "S2-2025", "S3-2025", "S4-2025",
]


# [4] GENERATE TARGET ASSET PATHS
def GenerateAssetPaths():
    TargetPaths = []

    # SiteOne Model Assets
    for Label in SiteOneLabels:
        for Suffix in ModelSuffixes:
            TargetPaths.append(f"{BasePath}SiteOne-{Label}-Model-{Suffix}")

    # SiteTwo Model Assets
    for Label in SiteTwoLabels:
        for Suffix in ModelSuffixes:
            TargetPaths.append(f"{BasePath}SiteTwo-{Label}-Model-{Suffix}")

    return TargetPaths


# [5] BATCH DELETE OPERATOR
def DeleteTargetedAssets():
    Targets = GenerateAssetPaths()

    if not Targets:
        print("[!] No active labels selected. Aborting.")
        return

    print("--- TARGETED ASSETS FOR PURGE ---")
    for Path in Targets:
        print(f" -> {Path}")
    print("---------------------------------")

    Confirm = input(
        f"Are you sure you want to PERMANENTLY delete these {len(Targets)} assets? Type 'YES': "
    )

    if Confirm.strip() == "YES":
        for Path in Targets:
            try:
                ee.data.deleteAsset(Path)
                print(f"[SUCCESS] Deleted: {Path}")
            except Exception as Err:
                print(f"[FAILED] Could not delete {Path}: {Err}")
    else:
        print("[ABORTED] Deletion canceled. No assets were touched.")


# [6] EXECUTE
if __name__ == "__main__":
    DeleteTargetedAssets()

How It Works Three steps, each doing one job.

Build the label set. Two lists hold the seasonal identifiers for each site. The year-per-line layout is deliberate — it lets you comment out an entire row to skip a year, or a single entry to skip one season, without touching the rest of the structure. If you want to purge only 2022 and 2023, you comment out every other row. If you want only the first season of every year, you comment out three entries per line.

Generate paths. GenerateAssetPaths crosses each label with each suffix and prefixes the base path. Whatever combination exists in your naming scheme — site, season, model type, variable — you add a nested loop for it. The function returns one flat list of fully-qualified asset paths.

Delete. DeleteTargetedAssets prints the list, waits for a typed YES, then calls ee.data.deleteAsset on each path. Failures are caught per asset, so a missing path or a permissions issue on a single entry doesn’t stop the rest. Every entry produces a [SUCCESS] or [FAILED] line.

Usage Set BasePath, ModelSuffixes, and the two label lists to match your naming scheme, then run:

bash python delete_assets.py You’ll see the entire path list printed before anything is touched. Read it. The script won’t proceed until you type YES.

Caveats Deletion is permanent. GEE has no trash and no undo. Once an asset is gone, it’s gone. Before running this on a large batch, export a manifest of the asset IDs — the printed list right before the prompt works as a record if you save it.

Verify the path list first. That printout is your last line of defence. If a single suffix or label is wrong, you’ll be deleting assets you didn’t intend to touch. Run the script with a small subset of the lists enabled first, confirm the output, then expand.

Comment out what you want to keep. The lists are the only input to the deletion set. There’s no exclusion filter beyond commenting out entries. If you need something more complex — a whitelist, a date cutoff, a cross-check against a saved manifest — wrap that logic around GenerateAssetPaths before the loop runs.

Check the IAM role on the account. Deleting assets requires write access to the parent folder. If a batch fails with a permissions error, the issue is with the account, not the script.

Folders are left alone. This script deletes leaf assets. It does not remove the folders that contain them. If you want the folders gone too, delete them separately after the leaves are cleared, or extend the script to walk containers the same way a folder-migration script does.
